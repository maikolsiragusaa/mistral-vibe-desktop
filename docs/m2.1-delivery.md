  stale-guarded hunk staging, app-managed worktree space
  (`userData/worktrees/<slug>-<sha1>/`), ownership-gated safe removal,
  read-only explorer/preview sources, `gh`-backed PR reads.
- `backend-pool.js`: `describeWorktreeUsage()` — frozen read-only ownership

  sandbox, no preload/Node), loopback-only URLs, same-origin redirect

  History, Worktrees, PullRequests); `GitWorkspace.tsx` orchestrates state

## CI / installer

Concluding commit `058a1aa`: **both Actions green** (push `38398875988`,
PR `38398882856`) — build, unit tests, backend probe, dev-app UI, NSIS
packaging, packaged-app UI, SHA-256 verification and artifact upload
(`Vibe-Desktop-Windows-<sha>-…`) all succeed with zero failed steps.

Post-mortem of the red interval (recorded, not hidden): the deterministic
cause was a missing `import { launchDesktop }` in `expansion.spec.ts`,
dropped by the M2.1 header edit — every dev-app UI run since `8cdcb55`
died with `ReferenceError` before launching. It escaped local detection
because passing runs executed a stale Playwright transform cache; the
`6ef8a22`/`89fd024` reds were this bug, not flakes. Genuine loaded-runner
variance was observed exactly twice (one PR packaged-app step on `bfdb4e9`
while its push twin passed; one local WMI teardown sample) and is
addressed by race-safe assertions, 30 s snapshot waits and one delayed WMI
retry — with per-step green on the concluding SHA as proof. Lesson: treat
a disappeared import as a P0 suspect whenever a suite fails at launch, and
distrust consecutive quick re-runs against transform caches.
