## Bugs reproduced (all confirmed before fixing)

1. **MCP field loss (A1).** `StdioMcpDialog.tsx` rebuilt `/mcp_servers` from a 9-field projection, dropping `startup_timeout_sec`, `tool_timeout_sec`, `sampling_enabled`, `disabled_tools` and unknown fields; `removeStdioServer()` shared the projection. Live probes proved upstream preserves unknown fields end-to-end while the desktop dropped them, contradicting the M4 preservation claim.
2. **Silent element-replace rejection.** `set` on `/mcp_servers/<i>` returns `status:"applied"` with `rejected:true` and changes nothing — the most misleading shape in the protocol.
3. **Secret exposure.** The env textarea was initialized with `KEY=value` plaintext in React state.
4. **Credential-guard overreach.** Desktop validation rejected `*_TOKEN` env keys anywhere, making token-based MCP servers (the canonical case) unconfigurable.

6. **Model-switch race.** The picker trusted the write receipt, which can predate the applied model (packaged CI first-attempt failure on `Model: GLM 5.3`).

## Architecture adopted

- **Single main-process `McpConfigService`** (`src/main/mcp-config-service.js`) behind circumscribed IPC (`vibe:mcp:describe`, `vibe:mcp:mutate`, trusted-sender verified like all channels). The renderer describes intent only (typed `mcp-mutation-types.ts`, pure builders in `mcp-intent.ts`, thin `mcp-config-client.ts`). No second config system, no vault, no local database.
- **Leaf-only writes**: `/-` append (or whole-list set on empty baselines only), per-field set, field remove, index remove. Whole-element replacement is never used.
- **Freshness + conflicts**: per-app mutex, re-read immediately before writing, SHA-256 revision check, unique-identity check, env keep-list check, neighbor canonical-JSON verification. Outcomes: `applied-verified | rejected | conflict | pending-reload | readback-failed | unknown`. No blind retries; no unsafe rollbacks.
- **Secrets**: renderer holds key names + explicitly typed values only; service merges env server-side from the fresh read; snapshots/results/messages are scrubbed (Bearer/token patterns, `KEY="…"` shapes); backend credential guard scoped to non-env paths.
- **Layers**: owning-layer resolution (pinned → single writable owner → first writable target → virtual empty on fresh homes). Edits to servers owned by read-only layers are **refused** instead of shadowed elsewhere.
- **Launchers**: `.cmd/.bat` custom editors refused (backend validation + stored-preference migration match); spawn confirmation waits for the OS `spawn` event with async-error handling; renderer copy says "process started", never "opened".
- **Model switch**: `writeModelAndConfirm` polls `runtime/read` (400 ms, ≤10 s) for the exact alias/effort; explicit pending notice on timeout. The spec waits for the authoritative alias before asserting the button (no inflated fixed timeouts, no version fallback, no new retries).

## Problems found & fixed (no lucky reruns)

1. **Fresh-home virtual layer.** The UI spec caught `describe` failing where only the `default` layer exists (unit fakes always had `user-toml`). Fix: resolve to the first writable target with a virtual empty list; adds write a whole single-entry list only when nothing exists.
2. **Credential-guard overreach.** The same UI spec caught `*_TOKEN` env rejection at desktop validation. Fix: scoped `mcpEnvScope` exemption, strictly inside `mcp_servers/*/env`.
3. **Ambiguous card selectors.** After a successful add, catalog + config cards both match the name filter. Fix: scope stdio assertions to `.rw-stdio-list`.
4. **Missing engine-ready wait.** The new spec pressed through the palette before the backend connected. Fix: wait for `.engine-status` 2.26.1 (authoritative state, same as expansion).
5. **Short-lived-dialog assertions.** Redaction checks moved to page-level locators (`getByDisplayValue` is unavailable in the pinned Playwright).
